# ScaleStack site

The public website for ScaleStack Tech (https://scalestacktech.co). The home page is a feed of real AI use cases for businesses, each summarised in our own words from one public source. ScaleStack also ranks AI video makers from what vendors publish (draft, under `/rankings/`). The research is Desk-researched: public vendor pages only, no hands-on tests. Every fact shows its source link and the date it was retrieved.

The site is a static [Astro](https://astro.build) build. It has no analytics, no forms, no server functions, no adapter and no tracking.

## What is in it

| Path | What |
|---|---|
| `src/data/tools.csv` | One row per tool. Every field has a `_source_url` and `_retrieved_date` column. `price_live_verified` is `false` until a person has re-checked the prices on the live vendor page. |
| `src/data/evidence.csv` | The text noted from each source page, one row per snippet, per tool and field. |
| `src/data/scores.csv` | Criterion scores (0, 3 or 5) with `evidence_url` and `evidence_quote`. Unchecked criteria score 0 with the note `UNVERIFIED: not yet checked`. |
| `src/data/rubric.json` | The six criteria, weights (sum 100) and 0/3/5 anchors. The methodology page renders from this file. |
| `src/data/ranking.json` | Generated by `scripts/score.py`. Commit it after running the script. |
| `scripts/score.py` | Reads `tools.csv`, `scores.csv`, `rubric.json` and `evidence.csv` only. Sorts by total score, ties alphabetical. |
| `src/data/use_cases.csv` | One row per use case: id, title, summary, category, tools, `tools_with_pages` (tool_ids that have a page), source_name, source_url, source_date (date shown on the page or `no date shown`), fetched_date, own_words_check, notes. Drives the home feed, `/use-cases/<category>/`, search and RSS. |
| `scripts/check_use_cases.py` | `python3 scripts/check_use_cases.py`: needs 30+ rows and 5+ per category, a source_url and fetched_date on every row, no duplicate URLs, no agentusecases.ai source, banned words, result-claim words in title/summary flagged, one-sentence summary. |
| `src/data/categories.json` | Category list for browsing. Only AI video makers is live; the others show "coming soon" with a count of 0. |
| `src/pages/` | Home (AI video maker directory), use case feed (`/use-cases/`), methodology, rankings (`/best/`, `/best/ai-video-makers/`), tool pages (`/tools/<id>/`), 404. |
| `src/pages/rss.xml.ts` | RSS 2.0 feed at `/rss.xml`, built from use cases (item date = `fetched_date`) and tool records (`date_added`). |
| `src/pages/search.json.ts` | Static search index at `/search.json`, covers use cases and tools, read by `public/search.js` in the visitor's browser. `public/feed.js` runs the home page category/tool chips and search filter. |
| `src/components/` | `ToolCard.astro` (card with summary, score or "Score pending", source link and date), `Search.astro`, `FieldRow.astro`. |
| `public/` | `robots.txt`, `llms.txt`, favicon, `search.js` (client-side search), `theme.js` (dark mode toggle). |
| `scripts/linkcheck.mjs` | `npm run linkcheck`: checks internal links in `dist/` and the `rel` on outbound links. |

## Build

Needs Node 20.3 or newer (Node 22 works) and, for scoring only, Python 3.

```
npm install
npm run build      # writes the static site to dist/
npm run preview    # serves dist/ locally
```

Re-run the scores after editing `scores.csv`, `tools.csv` or `rubric.json`:

```
npm run score        # rewrites src/data/ranking.json
npm run score:check  # fails if ranking.json is out of date
npm run build
```

`npm run build` does not run Python, so Vercel builds with Node only.

## Data rules

1. Public pages only. Every value needs a source URL and a retrieved date. If a page does not state a value in text, the value is `UNVERIFIED`. Do not fill gaps from memory.
2. A score above 0 needs an `evidence_url` and an `evidence_quote` that matches a snippet in `evidence.csv` for that tool. `score.py` rejects anything else.
3. Scores are 0, 3 or 5 only. If the evidence does not fully meet the 3 anchor, the score is 0.
4. Ranking uses total score only. Ties are alphabetical. Nothing else enters the calculation.
5. The scoring script reads no file other than the four named above. Do not add partner, payout or contact files to this repo.
6. `price_live_verified` stays `false` until prices are re-read on the live vendor page. While `false`, the tool page shows "Prices on this page are being re-verified".
7. Outbound vendor links are plain links with `rel="nofollow noopener"`: no tracking, no referral parameters.
8. The ranking pages carry a DRAFT flag and are left out of the sitemap (and set to `noindex`) until every score in `scores.csv` is checked. This happens on its own when `ranking.json` reports `complete: true`.
9. The "Updated" date on the home page is the latest `fetched_date` in `use_cases.csv`. Feed order is newest source date first; cards with `no date shown` come last.
9a. Use case rules: one public source page that was fetched and read (record `fetched_date`); own words only; no income, revenue, ROI or results claims shown as fact (leave them out, or write "the source reports" with attribution); vendor case studies say "reported by <vendor>"; no affiliate or tracking parameters; never use agentusecases.ai as a source; mark uncertain fields UNVERIFIED. Run `python3 scripts/check_use_cases.py` before building.
10. Cards show a score only when every criterion for that tool is checked. Otherwise they show "Score pending". Scores are never typed into pages by hand.
11. Dark mode follows the visitor's system setting until they press the toggle. The choice is stored in the browser only. No external requests, no third-party scripts.
12. The Prospecly box on the home page sits outside the feed and every ranking, and says so. Each card also carries the line "Want this built for your business? Prospecly, ScaleStack's own agency." linking to the internal page `/services/`. `/services/` is a plain page: no prices, guarantees, results or free offers, no forms, and it is not in any ranked list, category or tool browse. `scripts/check_services.py` (`npm run services:check`) checks that no `prospecly.ai` string remains in `src/`, `public/` or `dist/` and that the services page has no banned words.
13. No secrets, keys, private notes or personal contact details belong in this repo. `.gitignore` covers `.env` files.
